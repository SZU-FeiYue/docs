# 贡献

本页说明如何把经历写进手册，以及来稿之后如何发布。

手册需要的是当事人自己的记录。作者把事实写清楚即可；体例、归档和上线由[编写委员会](index.md#committee)处理。计算机相关专业之外的路径，以及结果并非「理想去向」的记录，同样收录。

## 流程 {#process}

1. **选定栏目**：留学、保研、考研或就业，按自己的实际路径选一栏。一条经历只归入一个栏目。
2. **取模板**：有对应模板则按模板填写；没有合适模板时，按「背景 / 结果 / 过程」自行分段。
3. **写完正文**：以申请或求职当时提交的材料为准，不要按后来的结果改写背景。
4. **投递**：邮件、微信发给维护同学，或向源码仓库提交 Pull Request。不要求自行排版。
5. **委员会处理**：确认栏目与毕业届，核对明显事实，按手册体例整理标题与分段，编入导航。
6. **发布**：随手册更新出现在对应栏目。维护同学可能就缺项通过你留下的联系方式询问，一般不必自己改网站。

## 稿件写什么 {#writing}

各篇原则上包含三项：

1. **背景**：绩点、竞赛、科研、实习等，以申请或求职当时的材料为准。
2. **结果**：完整投递清单，包括录取、拒信、候补和未回复，不要只留最终去向。
3. **过程**：信息来源、关键时间节点，以及事后仍认为有效的判断。

建议写到：

- 当时的成绩、竞赛、科研、实习，不要事后美化
- 完整投递列表，包括没过的项目或公司
- 时间线：何时开始准备、关键节点在哪
- 现在看来真正起作用的判断，以及给低年级的一句具体建议

署名可用真名、化名或匿名，在稿件开头说明即可。联系方式可选，用于委员会追问缺项，不必写进正文。

## 来稿之后 {#after}

委员会收到稿件后会依次做这些事：

1. 确认栏目与毕业届，必要时与作者核对去向和届次。
2. 核对明显事实（院校、项目名称、时间），不改你的判断与经验。
3. 按手册体例整理标题、分段和用语。
4. 编入对应栏目的导航，随手册发布到线上站点。

需要补充材料时，会通过邮件或微信联系。从投递到上线的时间取决于来稿是否完整，以及维护同学的处理节奏；作者一般不必跟进排版。

发布后的篇目按毕业届归档，新近届次列于前。正文按 [CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/) 授权，与手册其余部分相同。
